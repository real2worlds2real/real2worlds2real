# Template for a reconstruction experience module

Copy the structure below into a file named after the reusable method. Replace
the explanatory text with source-backed guidance; omit irrelevant details.
Keep the shared sections so future agents can find assumptions and checks.
Link the finished module from [the index](index.md). It is a reference within
the existing skill, not a new standalone skill or a session report.

---

# Descriptive method name

**Module id:** stable lowercase hyphenated id, also used in ledger context.

**Scope:** observable triggers, supported mechanism/settings and composition.

**Evidence status:** distinguish source-backed procedure, experimental candidate
and adopted finding in an identified context; cite records for adoption claims.

## Observations

Specify necessary source cues and how to distinguish them. Identify what is
observed, inferred or unresolved; note required additional views/evidence.

## Representation and parameters

Describe parts, surfaces, materials and functional frames. State parameter
relationships and supported model families. Explain conditions for switching
representation. Keep case-specific dimensions and fitted parameters out.

## Procedure

Describe the useful modeling/refinement sequence and any other experience
modules to compose. Name actual code/tool interfaces and their scope. Explain
which source checks must remain independent from task optimization.

## Checks and failure diagnosis

Pair failure signatures with discriminating diagnostics. Separate geometry,
native physics, semantic review and full-scene acceptance. Include failed
controls where they test the claimed mechanism. Avoid universal tolerances
copied from the first successful case.

## Implementation and evidence

Link shared APIs, applicable tests and validation records. Label historical
session scripts as provenance only if they contain old fitted values. State
which checks actually ran and what remains unvalidated. Distinguish a planned
shared helper from an existing one; do not invent CLI flags.

## Reuse limits

State applicability, known counterexamples, settings that need new evidence
and what must be re-estimated for a new source. Identify the next experiment
when evidence is incomplete. An old task pass is not a new scene approval.
