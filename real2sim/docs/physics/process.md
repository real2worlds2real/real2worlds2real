# Replicating physical processes from videos

`calibrated_scene_reconstruction.physics.process` is a physical estimation sub-module that can be called by real2sim. The goal is to replicate the observed processes using Isaac Sim 5.1, rather than defining a task and then applying fixed parameter tables. The agent develops and revises the physical model, while harness executes native simulations, joint searches, and recording and scoring. The module itself does not include services for automatically invoking language models.

For details on new video integration, revision division, and delivery steps, see [Video Physical Reproduction Process](process_workflow.md). This document retains the detailed protocols for each interface and measurement method.

## How to do one round

1. real2sim provides reviewed geometry, camera, and scale. agent combines video and optional robot/hand.
   Trajectory, listing objects, materials, stiffness-softness, drives, interactions, and observations requiring explanation.
2. Agent selects the original physical representation, writes the model, and decides which quantities need to be fitted and which can only be given as priors.
   Mass, contact friction, driving parameters, flexible material parameters, initial state; no fixed parameter name list.
3. Review the model structure, materials, mechanism, and native representation, then submit the plan. Place the model source code here.
   `configs/<Name>/agent/physics/`; running logs are stored in the input directory's `physics_process/`.
4. Harness fixes the model and geometry. First, save the results of default parameters, and then perform joint search for the parameters to be estimated.
   Only the fitted frames are selected as candidates; the held-out frames are used for acceptance and do not participate in candidate selection.
5. The agent checks for errors and the native state. If it fails, it revises the parameters/mеханизм, or requests a new geometry from the modeling cycle.
   Or record what observations are missing. The new round will be retained before the previous round, without covering history.
6. After passing the numerical evaluation, it still requires independent review of semantics, physical rationality, the entire process, and parameter evidence. Passed.
   The result can be returned to the real 2 sim; enabling its scenario in S5/S6 to check whether the evidence is still valid.

Do not use the actual object size for fitting or admission inputs. Physical fitting should not be used to secretly change scale, table height, or mesh to reduce motion errors. If there are geometric issues, return to modeling and review, and then establish a new physical plan. The driver should control the observed robot/external forces; the interpreted objects must freely participate in native simulations. It is not possible to directly replay the observed pose of the target object to achieve low error.

When reusing an old scenario, it is necessary to recheck the initial state of the new video. The same bottle does not mean that the sticks, flowers, or flexible parts inside remain in the old position; a central point of the whole cannot guarantee that the directions and occlusions of each part are correct. `process/initial_state.py` provides the initial fitting of source diagrams for independent straight rods, open supports, and rigid-flexible composite bodies, as well as minimal rigid body contact corrections that do not change the shape. Changing the length or opening belongs to the modeling stage and should not be hidden in the physical parameter search. `process/derived.py` saves the assumptions using a new USD layer, while the original scenario remains unchanged.

When the plan includes an `initial_state` input, or when the `model.initial_state_review` option is explicitly enabled, it is necessary to submit a partial review. The review involves hashing and associating videos, cameras, geometries, source code, observations, and auxiliary evidence listed in `model.initial_evidence`. Each dynamic body should be covered only once, and it’s allowed to group flexible parts together based on their relationships to the overall structure. Each group is carefully inspected for pose, structure, visibility, and contact details. The original execution check for `initial_state_source` remains essential. Internal structures not observed in the source image are recorded as prior knowledge, but cannot be considered fully identified. Static candidate renderings and mesh distances are merely preparatory checks. It’s still necessary to verify poses after the object is stationary, check actual contacts and entry points during movement, and compare actual renderings with the source image from the same perspective. Long segments that only have matching ends or wide-angle edges aren’t sufficient to prove that the entire geometry is correct. When clear rod segments are present, their position and orientation should be checked using `line_probes`. Each identified segment can be assigned its own channel to avoid averaging errors that might conceal deviations in certain parts. In cases where there’s no clear identification basis, unordered matching can be used. Masked skeletons may deviate from the actual axis at intersections, occlusions, and areas where the background overlaps with the skeleton itself. Such deviations cannot be used as definitive direction indicators. Candidate segments that shift after fitting to the source image must be reverted back to the contact model or geometric calculations. Pose locks, changes to observations, or compensation for initial state errors through friction parameters should not be used in this process.

Reusing the USD may inherit the linear velocity, angular velocity, and particle velocity from the previous run. When there is a clearly stationary segment in the source video, you can declare `model.initial_motion={"mode":"stationary","review":"motion_review"}`, and retain the `initial_kinetic_state` check. This checks the binding of the current video, camera, and observations. The harness clears the initial velocity of the dynamic rigid body and PBD responses before reset, saving `initial_kinetic_state.json`. This only sets the initial conditions; it does not clear the velocities during operation, nor does it lock the pose. If not declared, the old initialization method is retained. Joint systems, volume soft bodies, and inputs that are already in motion require corresponding initializations from the model itself; these cannot be applied to this rigid body/PBD stationary initializer. This check does not replace static positioning and contact verification.

When the initial state is not fully determined, the position/orientation can be treated as bounded parameters to be estimated. Friction alone cannot explain initial state deviations. `scene_model.initial_pose_parameters` is configured by parameter names: `kind` (rotation or translation), `roots`, `bodies` that are exactly covered by these root nodes, and `axis`. Rotation also includes a `pivot` parameter; the optional `reference_body` specifies a reference body to remain stationary. Angles are measured in radians, and translations in meters. `process/initial_pose.py` applies a rigid transformation only once before reset/free standing, preserving the relative mesh and mass properties of the rigid-flex composite bodies. The results are recorded in `initial_pose_parameters.json`. It rejects static supports, missing parts within groups, and joints fixed to the world; all interactions between sources, standing, and movements must still be fully executed. These parameters are estimates of the initial state, not measured material parameters. The order of parameters determines the composite sequence of multiple transformations.

When multiple loose components are contained within a container, they should be examined together with the remaining objects. Examining only "rods and containers" would overlook the initial overlap between "rods and flower rods." This overlap can cause objects to be squeezed apart during static conditions, leading to incorrect interpretation of the initial state due to friction fitting. `process/contact_initial.py` performs source graph fitting for small straight rod contact networks, including support ranges, contacts between independent rods, other rod-like obstacles, and identity associations for conforming parts. It generates only bounded modeling assumptions and cannot replace verification of native equilibrium. Association selection and optimization are performed on read-only fitting frames. Levels retain independent source graph endpoints, directions, region sizes, and native contact checks; the overall center point cannot be used as a substitute.

When in a native equilibrium state, `fit_seated_segments` can be constrained by `azimuth_bounds` to modify the source map, constrained by `azimuth_groups` for joint rotation, and the identity assumptions are explicitly listed using `assignments`. By default, the original angle range and identity arrangement are still searched for. This method is only applicable to approved axisymmetric contact assumptions, and no guarantee is given that new candidates will remain stable. When the length of a uniform cylinder is changed, `stretch_uniform_cylinder` simultaneously updates the display mesh, collision mesh, mass, centroid, and principal inertia, while maintaining the density prior. Complex materials and shapes must use their own mass models.

Thin long rods cannot be checked only at mesh vertices: Only cylinders with ring vertices at both ends may have their middle sections passing through another rod or bottle mouth. Complete surface sampling can be used during the preparation phase; when it is confirmed that the rod and circular inner walls are of equal thickness, axial cross-sections of the source model can also be used as constraints. Multiple rods should be combined to find the minimum rigid body translation, avoiding transferring penetration to neighbors when moving them individually. `seat_cylinders` does not add fixed connections; still, contact must be established at each step using native methods. Ordinary complex shapes cannot use the rod assumption; distance queries for large meshes should be performed in small batches to avoid excessive memory usage by candidate triangle arrays.

The observation definition must correspond to the complete surface in the source image. When an area contains both rigid structures and flexible surfaces, `scene_model.landmark_groups` can declare rigid material sub-mesh using `surfaces`, which is then projected together with the flexible point mesh in `bodies`. It is not possible to only project the flexible parts and compare them with the entire area of the source object; this could lead to misinterpreting differences in observation definitions as errors in geometric or physical parameters.

Color threshold extraction identifies a subset of pixels at the current brightness level, which may not be a complete material area. Reflection, shadows, or exposure variations may cause it to select different parts before and after the video, creating a false motion error. Complete areas are available. `tools/physics/observe_masks.py` Extract from the reviewed source image semantic mask; review the bound segmentation manifest, declare identity and integrity per frame, and keep missing or incomplete areas as such. `region_observations.measure` Share the centroid/ranges calculation and morphological operations with native materials. Do not use large core erosion on only one side just to remove thin rods. Non-empty segmentation cannot replace source image review.

New plans can use `model.observation_definitions` to declare `part`, `scope`, `feature`, and `opening` by predicted keys; `observation_review.definitions` provide the same definitions by observed keys. The contract disallows mixing `photometric_subset` with `complete_part`. The harness also verifies the actual `observation_definitions` returned by the model and preserves the native declarations. `scene_model.marker_region` only provides complete material projections and cannot be renamed as a color subset or an observer for occluded surfaces. Old point trajectories and models without this protocol remain with their original interfaces; once a region channel is defined, it cannot be deleted if it fails.

The `scene_model` can configure `initial_landmarks`, `initial_checks`, `initial_split`, and `aperture_check`. It checks the endpoints of independent rods, axis orientation, the size of flexible areas, and the cross-section of finite rods passing through openings. The fitted view and held-out views are scored separately, and occluded observations remain NaN. The default old model continues to be compatible; once new reviews are enabled, subsequent revisions cannot remove it.

Source image errors are considered observations and cannot be used as hard physical filtering conditions that include held-out frames. When initial state verification is enabled, `model.observation_checks.initial_state_source` must list the IDs of the corresponding `channels`. Optimization is only performed on the fitting frame errors of these channels, while still requiring all fitting, held-out, and native physical checks to pass. The declared conclusions of the source image checks must be consistent with the bound channels. True physical failures, such as contact penetration or invalid native states, will still reject candidates; they cannot be marked as observations to allow optimization to continue.

For components that are the same and unlabeled, use `channels[].metric=unordered_points`: the observation array is `time×number of components×coordinate dimension`. Integer NaN values represent invisibility. In each frame, only one-to-one matching is performed between the visible subset and the native prediction. It does not prove continuous identity correspondence; components with identified identities should still retain named channels. Angles are measured using `metric=angular`, with support for interpolation across ±π and error comparison. Key motion phases can be assigned separate channels to avoid diluting short-term error responses during periods of prolonged inactivity.

When fitting contact parameters, the range of application must also be checked. `scene_model` retains the old `pair_material_binding=both_average`, and provides `support_min`: only applying low-friction materials to the support surfaces. The min combine is used to achieve lower support contact coefficients, while retaining the materials of the target object and internal objects. This mode requires that the target material coefficient is not lower than the requested value, and the original combine must be either average or min. Otherwise, the request is explicitly rejected. It applies only to low-friction support models that meet these conditions; it is not used for friction estimates of any object pairs. When enabled, the native checks and readback records for `contact_parameter_scope` are retained.

`scene_model.contact_parameters` allows for binding planned parameters to declared native material coefficients. The optional `linked: [{attribute, factor}]` indicates a specific proportional prior, such as the ratio of static to dynamic friction. Binding conflicts will be rejected, and both the main coefficient and the linked coefficient will be saved for rereading. When there is no observational basis for the proportion itself, it must be retained as a prior; it cannot be claimed that both coefficients are independently identified. If the initial static state matches but the sliding behavior after applying force does not, this proportional assumption should be re-examined. It is possible to declare static friction and dynamic friction as two parameters, binding them to two attributes of the same material. Retain the prior of static support before verifying the sliding response; combine estimates when there is sufficient evidence. Lower friction candidates cannot be accepted by eliminating the initial state check or treating actual contact issues as image errors.

`scene_model.mass_parameters` can explicitly bind the masses of other rigid bodies, no longer fixing the masses of all internal objects as unverified default values. Each declaration of `bodies` and `mode`: `scale` multiplies the source mass and principal inertia together with the parameters; `absolute` sets the mass to the parameter value and updates the principal inertia proportionally. The center of mass and principal axes are retained. Bindings cannot be repeated, nor can they overlap with `object.mass`; positive mass/inertia values must exist first. The mass model for soft bodies is still handled by the corresponding native material model; scaling of the rigid body core cannot be considered as scaling of the entire soft body assembly. When enabled, the `additional_mass_readback` check and `additional_mass_bindings.json` are retained. Masses may be coupled with unknown external forces, and the mass ratios between different parts may vary. Reading back does not mean that the masses have been uniquely identified.

## Input and planning

The complete JSON schema can be accessed through the `physics_propose` query in `calibrated_scene_reconstruction.agent.tool schemas`; cross-file and physical constraints are checked by `process/contract.py`.

| Field | Contents |
| --- | --- |
| `inputs` | Named Files: Video, Camera, Robot Trajectory, Geometry, Model Source Code, Model Review, Priori, Auxiliary Input |
| `model.bodies` | materials, representations, sources, reasons for each part, and static/dynamic/ prescribed |
| `model.interactions` | How do certain parts of a robot interact with each other through physical mechanisms? Why is this necessary? |
| `model.required_checks` | Name of the physical rationality check that must be passed in this round |
| `model.physical_limits` | Clearly defined upper limit of positive numbers for agents, such as allowable penetration |
| `parameters` | Any named parameter, including initial value, prior range, unit, object of action, reason, and fit/prior_only |
| `observations` | NPZ input containing `t` and observation channels; occluded samples represented by NaN |
| `observation_review` | Review of newly extracted source images, check identity, camera, occlusion, time; bind video/camera/image with hash. |
| `channels` | Measured/predicted array keys, units, tolerances, weights, and reasons, such as posture, contour, liquid level, deformation, or event characteristics |
| `comparison` | Non-overlapping fit frames and held-out frame indices, with at least two valid observations per channel |
| `simulation` | Isaac Sim 5.1, model entry, step size, duration, explicit pre-stabilization time, and state recording budget |
| `search` | Population, generation number, random seed, timeout, and single-parameter sensitivity sampling quantity |
| `revision` | Subsequent rounds of the parent round, failure explanations, assumptions, and specific changes |

`model.review` refers to the review file, which must contain `pass`, `reason`, and four explicit checks for `structure/materials/mechanisms/native_model`. All `geometry` and `model_source` inputs must be bound using a `inputs` hash. Additional code, USD dependencies, and data used by the model should also be declared. The model must not implicitly read from previous fitting results or evaluate ground truth. Review records are written after the agent checks the evidence. The harness does not automatically perform semantic reviews on models.

Robot trajectory requires explicit joint names, coordinate systems, and clock alignment. The existing `models.robot_replay` utility assigns joint names, gripper commands, and optional measured end-travel paths, recording actual joint responses; unknown joints are reported as errors. When there is a discrepancy between the commanded trajectory and the actual execution, additional execution observations, drive parameters/error models, and corresponding acceptance channels should be added. All errors should not be absorbed through contact friction. This helper currently does not automatically align time.

## agent interface

CLI and MCP expose the same set of tools. CLI example:

```bash
PYTHONPATH=src envs/recon/bin/python -m calibrated_scene_reconstruction.agent.tool schemas
PYTHONPATH=src envs/recon/bin/python -m calibrated_scene_reconstruction.agent.tool physics_propose \
  --request request.json --output outputs/process_proposal
```

The structure of `request.json` is `{"session":"<input directory>","plan":{...}}`. Python calls can also directly pass the plan:

```python
from calibrated_scene_reconstruction.physics.process import workflow

workflow.propose(recording, plan)
workflow.run(recording)  # Executed via shared GPU launcher; synchronization wait, subject to scheduled timeout limits
state = workflow.status(recording)
# Agent checks errors and native evidence, as required: request_geometry / request_observations / propose.
# Numerical values are submitted for independent review after passing the review; they can only be accepted thereafter.
```

| Tool | function |
| --- | --- |
| `physics_propose` | Submit a plan, or create the next round with revision notes |
| `physics_run` | Execute current plan; return deferred when memory shortage occurs, and the same round can be retried. |
| `physics_status` | It can also query the status while running, and lack of evidence is not considered as a pass. |
| `physics_request_geometry` | Modeling the iterative revision process with requests for bodies, reason, and changes, then re-reviewing |
| `physics_request_observations` | What is missing? The impact of not having it. |
| `physics_review` | Review the current results and native evidence. If the value fails, it cannot be approved. |
| `physics_accepted` | Returned Parameter Evidence, Model, Input, Native Scenario, and Replay Record |
| `physics_attach` | Attach the recording evidence to the session, enable scene delivery check |
| `physics_prepare_legacy` | Convert recorded observations and trajectories; do not import old fitting conclusions |
| `physics_legacy_recipe` | Return to the original replay/video/soft tool command, maintaining the old capabilities. |

Final review includes `result_sha256`, `pass`, `reason`, `checks`, and `evidence`. `checks` must pass explicitly through `model_semantics/physical_plausibility/whole_process/parameter_evidence`; `evidence` binds the checked native state, rendering, and other files with relative paths within the iteration and SHA256.

## Native Model Protocol

When the source texture points are lost due to endpoint consistency checks, you can use `tools/physics/audit_surface_tracks.py --plan <source_plan> --output <new_directory>` to check the one-way tracking, individual endpoint errors, and the final number of valid frames in the source video. First, review the original image to identify occlusions, misidentifications, or labeling errors. Do not use simulation to predict missing points, nor should you automatically relax the consistency threshold. After correcting the labels, retain the old version and regenerate the observations and re-audit the source image.

The assumption of zero distortion for the camera is one that needs to be reviewed. The command `tools/physics/refine_static_intrinsics.py --source <COLMAP model> --output <new directory>` can be used to compare static camera fitting results. Additionally, `--refine-distortion` is used to test OpenCV distortion parameters. The tool first removes all observations from the BA for a set of static three-dimensional points, then triangulates these points using the fitted view. The error is calculated in the held-out view. The motion of the target object is not included in this camera model selection process. Training a reprojection method that is slightly less effective cannot replace static held-out evidence; the output also does not automatically approve metric registration or full physical reproduction.

The fitted plane for the desktop point cloud does not necessarily provide a reliable vertical direction of the world. When there is a clear vertical structure in the manufacturing process, `process.camera_gravity.estimate` can estimate the direction using the source lines of different columns, and requires independent verification from another column that is not involved in the fitting. This is a structural prior, not a measurement from an IMU. `camera_registration.register(..., plane_orientation='source_direction', normal_source=..., prior_reason=...)` can be used to re-regulate this; camera, initial state, and motion parameters need to be re-verified. It is not acceptable to simply rotate the camera and continue using the force direction from the old coordinate system.

The model source code provides `create(world, stage, parameters, inputs)`, returning:

- `bodies`: The `{path, kind}` of each plan's body. Kind supports rigid, static, particles,
  Deformable; it is necessary to bind the actual native physical schema. The joint system can record the original links of interest, and additionally record the actual joint states of the entire system.
- `consumed_parameters`: All actual plan parameter names that must be accounted for without omission.
- `driver_bodies`: Exactly the same as the prescribed objects in the plan.
- `observe(t, native_states)`: Exports observation channels from the native states. It cannot return the target trajectory as a prediction.
- `checks(trace)`: Returns a tuple of `{pass, reason}`; covers at least the required_checks.
- Optional `after_reset()`, `drive(t)`, `settle()`, `joint_states()`
  `after_settle_step()` (contact check of the native state after each pre-settle step), `after_step()` (measurement of native contact or material per step), `effective_parameters`, `readbacks(rigid_handles)`. `readbacks` returns `{ParameterName: {value, basis}}`. The `harness` corresponds to the request values, and the `helper` has implemented quality readbacks.

World, reset, clock, step, and state records are managed by harness. `drive` Robot commands/externals cannot transmit dynamic response objects. Solid static geometry is hashed for comparison between candidates; changes in shape require a new round of review. The declared initial state can vary within the corresponding native model. Shape inspection includes 1e-6 Numerical quantification cannot replace geometric quality inspection. `inputs['_process_context']['physical_limits']` Provide the stated physical limits.

The native trace is sampled at simulation steps near the observed time, preserving the actual clock. Inspection can only prove the sampled state, not continuous contact proof. When more detailed contact/material inspection is required, corresponding native measurements should be arranged in the model, or additional reliable sampling channels should be added. Each round has a duration, number of candidates, and trace budget.

## output and credible range

Each round of saving plans, input and harness hashes, observations, and model source code copies, default replays, search history, sensitivity tests, the initial USD for each candidate native, state NPZs, prediction NPZs, physical checks, and parameters. Changes to geometry/input/code/outputs can invalidate old evidence; new rounds and data requests can also render attached scenario-delivered evidence invalid. Failed rounds cannot be made valid by deleting observations or releasing errors.

Results are distinguished by prior_only, unconstrained_on_scan, and fitted_not_uniquely_identified. If declared as "fit", but the default candidate passes and the search is skipped, or the controlled candidate does not change this parameter, it will be marked as `not_varied_in_search`. It cannot be claimed that fitting has occurred based solely on the parameter listed in the plan. Single-parameter scanning is only a sensitivity analysis; it does not prove that multiple parameters can be uniquely identified. The prior range is not a confidence interval. Held-out frames belong to the same recording and are not cross-video generalization validations. Independent recordings are required to verify the parameter transfer capability.

`accepted.native_scene` is the preferred native initial USD, along with models, inputs, and drive/state records. The caller uses these to reproduce the process. `attach` only publishes audit receipts and delivers levels; it does not overwrite the frozen scene, nor does it automatically inject any parameter names into the old scene exporter. Actual runtime and task feasibility still require its original checks.

The framework allows the agent to provide multi-object, flexible, and joint models, but this does not mean that any physical inverse problem has been completed. Currently, tools such as robot rigid body playback helper, native scene reuse factory, and old video converter are available. The specific joint recognition models for special physical objects still need to be established by the agent, tested, and reviewed. Old demonstrations cannot be regarded as newly verified capabilities.

## Mobile cameras and video of people without a track

Separate the movement of the camera from the movement of the object. `tools/physics/observe_camera.py` After shielding moving objects, hands, and occluded areas, build a static map using CPU COLMAP. `export_camera.py` Export map `process/camera_registration.py` Established scales using reviewed initial geometry and static desktop setups. The internal parameters of the new video still need verification; the focal length of the old video cannot be directly inherited.

`process/vision.py` provides static map relocating, optical flow tracking, and material region observation configured according to the source map. `tools/physics/track_camera.py` allows reverse tracking, and `reconcile_cameras` is used to compare two directions: missing states can only come from independent static feature positioning and cannot be filled in by target object motion or interpolation; conflicting positioning is retained as missing. The basis for the desktop normal must be specified when it does not cover key motion stages. When the camera does not cover critical motion stages, unverified states are retained, and observations are supplemented or the camera is repaired instead of approximating projection errors as friction.

`process/plane_bridge.py` is a conditional static plane tracking: it adds image features only in approved plane areas, using forward and reverse closed-loop verification with two independent camera endpoints. If the endpoints do not close or the directions are inconsistent, the missing data is retained without using the bridging result. It is not the default solution for unknown desktop/unknown focal length; plane masking, active area shielding, and camera priors still need to be reviewed.

The newly extracted channels should be submitted to `observation_review` (pointing to an auxiliary JSON input), whose `inputs` contain the SHA256 values of all video/observations/camera inputs. The `checks` ensure that each item passes the identity/camera/occlusion/timebase criteria, with explanations provided for each check. The review includes an overlay of source images, particularly checking for backgrounds of similar colors, and ensuring that hands and targets are not confused. Once this review is planned to be enabled, failed attempts cannot delete it. The old observation converter remains compatible, and unchecked reviews are not automatically supplemented.

`process/proposal.py:linear_step` can generate a limited local joint correction from the same round of native candidates that have passed physical inspections. It only uses fitted frames, rejects rank-deficient/malicious perturbation designs, and does not consider recommended values as simulations or evidence. The new candidates still require new native operations.  `tools/physics/propose_process_step.py --round <Round> --output <New JSON>` provides this entry point. Use `--physical-steps <JSON>` to declare the maximum correction amount in the physical unit for each quantity, to avoid inappropriate scale for forces, friction, and minor contact eccentricity due to a uniform step size; local regression reduces the weight of distant tests based on distance. `--objective feasibility` prioritizes reducing the maximum normalized error in each channel. The original total error method is still available. The output also records the local model’s training error. A linear prediction alone is insufficient to establish that the check passed. For long-running tasks, you can explicitly add `--history-only` to only read the complete history of workers whose sources remain unchanged and who have already started. This will verify the hash of each candidate prediction and record the hash of immutable byte prefixes. The last line that is not completed will not be included in the fitting. This entry does not have the necessary execution credentials to store results. Therefore, it cannot be approved for this source round. It only proposes new experiments, which must be re-approved through the complete Isaac, source graph, held-out data, and manual review. The held-out frames are not involved in the local model fitting.  `search.stop_when_fit_passes=true` can stop subsequent searches when the default candidate, an explicit proposal, or a complete generation of CMA has met all fit errors and physical checks; this decision does not consider the held-out errors, and the held-out frames are still checked. By default, `search.objective=feasibility` first reduces the maximum fit level to avoid offsetting a failed item with lower errors of other items; then, it compares the original training loss after all fit levels are met. The original error with `fit_loss` remains, and the optimization priority is noted separately as `search_score`.  The `training_loss` option retains the original total training loss objective. Neither target reads the held-out error. For controlled experiments or local modifications, use `search.proposals` to clearly list the limited candidates, along with `proposals_reason`. Each candidate must provide all fit parameters within the original declaration range. The prior_only parameter cannot be changed; the number of candidates cannot exceed the original search budget. First, perform the default playback. Candidates are selected based on the fitted frames and hard physical conditions. Finally, check the held-out frames. Leave this field empty to keep the original CMA-ES search unchanged.

`tools/physics/visualize_process.py --round <Round> --output <New Directory>` Outputs a comparison chart of source observations and native predictions. Adding `--video-input <Named Video Input>` allows for the overlay of 2D pixel channels. This is a feature diagnostic video, not a rendering video of a simulation scenario, nor a declaration-based one.

When a comparison between real-time video and simulation scenarios is required, use `apps/physics/render_process.py` to render approved native USD, rigid pose, and PBD point states, along with corresponding camera trajectories. This tool disables dynamics in the anonymous session layer, rendering only the recorded physical results without re-fitting or interpolating shapes. `--camera-input` / `--video-input` specify the planned named input; the default values are `process_camera` / `video`. The camera NPZ includes `t/K/dist/T_world_cam`.

```bash
PYTHONPATH=src tools/run_shared_isaac.sh apps/physics/render_process.py <recording> \
  --output <New Rendering Directory>
```

Before independent review, it is necessary to add `--candidate` to the command. This option only applies to those instances that have completed the `awaiting_review` phase without any changes or errors. The default delivery path still requires approval from the official review team. Candidate renderings cannot be approved as final results. Outputs can be stored in the sub-directory of that round of review, and their hashes can be included in the review process after checking the videos. If you need to obtain detailed information about failed experiments, you can use `--diagnostic`. This option only applies to those failed/rejected experiments that have complete evidence, no changes, and valid candidate solutions. The video will be marked as “FAILED CHECKS”. It cannot approve results or replace official deliveries. The default rules for rendering remain unchanged compared to `--candidate`. If the current round is interrupted and you need to review previous failed results, you can use `--diagnostic --round <number>`. This option examines the results from previous rounds, successful executions, and valid candidate hashes. It does not affect the current round, does not accept unfinished experiments, and cannot be used for candidate review or official delivery. Time matching is determined based on `simulation.dt / 2` of the selected plan. It does not depend on the step size of a specific experiment.

`tools/physics/segment_process_video.py` Extract the real contour based on the source image segmentation plan of the agent.
